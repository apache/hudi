# Hudi AI Operator

Claude Code Skills for the people who deploy, operate and manage Apache Hudi tables: the ones who
own the writer properties, get paged when ingestion stalls, and have to decide whether a thing is
broken or merely slow.

This is the counterpart to `hudi-agent-gateway`, which serves the other persona — people who
*consume* data from Hudi tables, through SQL, a chat interface, or an MCP endpoint. That side cares
about querying. This side cares about whether the table underneath is healthy, laid out well, and
configured the way its owner thinks it is.

## What is here

| Skill | Question it answers | What it drives |
|---|---|---|
| [`hudi-table-health`](skills/hudi-table-health/README.md) | Are the table services keeping up? | `HoodieTableHealthChecker` |
| [`hudi-mdt-health`](skills/hudi-mdt-health/README.md) | Is the metadata table caught up and trustworthy? | `HoodieTableHealthChecker` (metadata checks) |
| [`hudi-table-layout`](skills/hudi-table-layout/README.md) | Is the data laid out well? | `HoodieTableLayoutAnalyzer` |
| [`hudi-rca`](skills/hudi-rca/README.md) | Why did this break? | A catalog of known failure patterns |
| [`hudi-config-consultant`](skills/hudi-config-consultant/README.md) | What does this config actually do? | A catalog generated by `scripts/generate_config_catalog.py` |
| [`hudi-optimizer`](skills/hudi-optimizer/README.md) | This works — could it be better? | `HoodieSparkEventLogAnalyzer`, plus the health and layout tools |

The tools live in `hudi-utilities`; each has its own `.md` runbook beside the class. The Skills are
the interpretation layer on top: they choose the flags, read the JSON, and explain the verdict.

## How the pieces fit

The split is by question, and the questions do not overlap much:

- **Health** is about cadence. Compaction, cleaning, archival, savepoints, metadata sync — is each
  service running often enough for the write rate it is behind?
- **Layout** is about shape. How bytes and files spread across partitions, whether the table is
  micro-partitioned or piling up small files, which partitions are hot.
- **RCA** is about failure. A job died; walk the `Caused by` chain, classify it, and give an ordered
  mitigation ladder.
- **Config consultant** is about reading. Not the key and its default, which the docs already give,
  but where the value is read, what gates that read, and what is read alongside it.
- **Optimizer** is about the middle case: the job runs, it is correct, and it costs more than it
  needs to.

Several Skills deliberately **delegate detection to the tools rather than re-implementing it**. The
optimizer runs the health checker and the layout analyzer rather than carrying its own copy of those
heuristics; the mdt-health Skill drives the same `HoodieTableHealthChecker` binary as table-health,
narrowed to the metadata checks. One detection implementation, in Java, with tests — the Skills add
judgement on top of it, and a fix to a detector reaches every Skill at once.

Skills also hand off to each other by name. `hudi-optimizer` stops at anything that would change
what is on storage — table type, index type, partitioning — and hands the measurements to
`hudi-architect` (in `hudi-agent-gateway/skills/hudi-architect`) for an Architecture Decision
Record. If the job is failing rather than slow, that is `hudi-rca`.

## Install

Each Skill is a self-contained directory. Copy the one you want:

```bash
# From the root of a Hudi checkout.
SKILL=hudi-ai-operator/skills/hudi-table-health

# user-level (available in every project)
mkdir -p ~/.claude/skills && cp -r "$SKILL" ~/.claude/skills/
# or project-level
mkdir -p .claude/skills && cp -r "$SKILL" .claude/skills/
```

Then invoke it by name in Claude Code — `/hudi-table-health`, `/hudi-rca`, and so on.

Most of these Skills need the `hudi-utilities-bundle` jar from the same Hudi release, reachable from
wherever Claude Code runs commands, plus read access to the table's base path. The tools are
read-only and never modify the table. `hudi-config-consultant` is the exception: it needs no jar, no
cluster and no table, because it reads only its catalog file.
